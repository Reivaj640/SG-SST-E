# v0.1.88 - Fix: Espaciado Módulo Recursos

**Fecha:** 21 de marzo de 2026  
**Versión:** 0.1.88  
**Tipo:** Fix visual / UX  
**Módulo afectado:** Recursos (home)

---

##  Problema Identificado

### Síntoma
Espacio excesivo (~6rem / ~96px) entre los widgets de estadísticas y las gráficas en el módulo Recursos.

### Captura del Problema
![Espacio excesivo](../utils/actual.png)
*El recuadro azul muestra el espacio que no se podía reducir*

### Intentos Fallidos
Inicialmente se intentó reducir el espacio modificando solo las propiedades locales en `recursos-home.js`:
- `.main-area { gap }` - Reducido de 1.5rem a 0.25rem ❌
- `.charts-grid { gap }` - Reducido de 1.5rem a 0.75rem ❌
- `.charts-grid { margin-bottom }` - Reducido de 2rem a 0.5rem ❌

**Resultado:** El espacio visual permanecía igual.

---

## 🔍 Análisis de Causa Raíz

### Estilos Globales en Conflicto

Se identificaron **TRES** archivos CSS con estilos globales que sobrescribían los estilos locales:

#### 1. styles.css (línea 1833-1839)
```css
/* Espacio extra entre secciones grandes */
.widget,
.panel,
.card-block,
.white-box,
.info-box {
    margin-bottom: 2.5rem !important;  /* ← AGREGA 40px DESPUÉS DE CADA WIDGET */
    padding: 1.5rem !important;
}
```

#### 2. styles.css (línea 1851-1855)
```css
/* Separación entre gráfico y las listas */
.chart-container,
.fc-view-container,
.table-responsive {
    margin-top: 2.5rem !important;  /* ← AGREGA 40px ANTES DE GRÁFICAS */
    margin-bottom: 3rem !important;
}
```

#### 3. development-styles.css (línea 718)
```css
.widgets-container {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
    gap: var(--spacer);
    margin-bottom: var(--spacer-lg);  /* ← AGREGA 24px EXTRA */
}
```

### ¿Por qué no funcionaron los intentos iniciales?

Los estilos locales en `recursos-home.js` se inyectan dinámicamente en el DOM, pero:
1. Los estilos globales tienen `!important` → Mayor prioridad
2. Los selectores globales (`.widget`) aplican a TODOS los widgets
3. La especificidad era igual (1 clase vs 1 clase) → Gana el último en cargarse

---

## ✅ Solución Implementada

### Estrategia
Aumentar la **especificidad** de los selectores locales usando el scope del módulo (`.gestion-integral-home`) y manteniendo `!important` para igualar prioridad.

### Código de Solución

```css
/* =========================================
   ANULAR ESTILOS GLOBALES (styles.css)
   Los estilos globales con !important están
   causando espacio excesivo entre widgets y gráficas
   ========================================= */

/* Anula: styles.css línea 1833-1839 */
.gestion-integral-home .widget {
    margin-bottom: 0 !important;
    padding: 1rem !important;
}

/* Anula: development-styles.css línea 718 */
.gestion-integral-home .widgets-container {
    margin-bottom: 0 !important;
    gap: 1rem;
}

/* Anula: styles.css línea 1851-1855 */
.gestion-integral-home .chart-card {
    margin-top: 0 !important;
    margin-bottom: 0 !important;
    padding: 0.75rem !important;
}

/* Anula: styles.css línea 1851-1855 */
.gestion-integral-home .charts-grid {
    margin-top: 0 !important;
}
```

### Ajustes Adicionales

```css
/* Main Layout - Espacio entre contenedores */
.main-area {
    display: flex;
    flex-direction: column;
    gap: 1rem;  /* Espacio final ajustado */
    overflow-y: auto;
    padding-right: 0.5rem;
    width: 100%;
}

/* Layout Grid para los Gráficos */
.charts-grid {
    display: grid;
    grid-template-columns: 2fr 1fr;
    grid-template-rows: auto auto;
    gap: 0.75rem;  /* Espacio interno entre gráficas */
    margin-bottom: 0.5rem;  /* Margen inferior */
}

/* Tarjetas de gráficas */
.chart-card {
    padding: 0.75rem !important;  /* Padding interno reducido */
}

/* Títulos de gráficas */
.chart-title {
    margin-bottom: 0.5rem;  /* Margen inferior reducido */
}
```

## 📊 Resultados

### Comparación de Espacios

| Propiedad | Valor Original | Valor Final | Reducción |
|-----------|---------------|-------------|-----------|
| `.main-area { gap }` | 1.5rem | 1rem | 33% ↓ |
| `.charts-grid { gap }` | 1.5rem | 0.75rem | 50% ↓ |
| `.charts-grid { margin-bottom }` | 2rem | 0.5rem | 75% ↓ |
| `.widget { margin-bottom }` (global) | 2.5rem | 0 (anulado) | 100% ↓ |
| `.chart-card { padding }` | 1.5rem | 0.75rem | 50% ↓ |
| `.chart-title { margin-bottom }` | 1rem | 0.5rem | 50% ↓ |

### Espacio Visual Total
- **Antes:** ~6rem (~96px)
- **Después:** ~1.5rem (~24px)
- **Reducción:** **75% menos espacio**

### Impacto en UX
- ✅ Más información visible en pantalla
- ✅ Mejor densidad de datos
- ✅ Scroll reducido
- ✅ Mantiene coherencia visual con sistema K+AIR

## 🎓 Lecciones Aprendidas

### Para Nuevos Desarrolladores

1. **Verificar estilos globales** antes de modificar estilos locales
2. **Usar selectores con especificidad** cuando se trabaje dentro de un módulo:
   ```css
   /* ❌ EVITAR: Selector genérico */
   .widget { ... }
   
   /* ✅ USAR: Selector con scope */
   .gestion-integral-home .widget { ... }
   ```

3. **`!important` con moderación** - Solo cuando sea necesario anular estilos globales
4. **Inspeccionar múltiples archivos CSS** - `styles.css`, `development-styles.css`, y CSS de módulos

### Patrón Recomendado para Futuros Módulos

```css
/* En el injectStyles() de cada módulo */
.<scope-del-modulo> .widget {
    /* Estilos específicos del módulo */
}

.<scope-del-modulo> .chart-container {
    /* Estilos específicos del módulo */
}
```
