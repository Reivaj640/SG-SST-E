# 🔧 v0.1.88 - Fix: Eliminación de Archivos en Google Drive

**Fecha:** 21 de marzo de 2026  
**Tipo:** Fix crítico  
**Módulo afectado:** 1.1.1 Responsable del SG-SST  
**Archivos principales:** `main.js`, `responsable-sg-viewer.js`

---

## 📋 Resumen Ejecutivo

### Problema
Los archivos Excel (.xlsx) en carpetas de **Google Drive File Stream** no podían ser eliminados desde la aplicación, mostrando el error:
> *"Google Drive tiene el archivo bloqueado. Cierra Google Drive temporalmente e intenta nuevamente."*

### Causa raíz
1. **Método incorrecto de papelera:** `shell.moveItemToTrash` no existe en Electron 10+
2. **Reintentos insuficientes:** 5 intentos × 2s = 10s era insuficiente para archivos grandes
3. **Sin liberación de handles:** Windows mantenía locks activos en archivos Office
4. **Google Drive indexación:** Archivos Excel >1MB requieren más tiempo para liberarse

### Solución implementada
1. ✅ **Corrección de API:** `shell.moveItemToTrash` → `shell.trashItem`
2. ✅ **Liberación de handles:** Abrir/cerrar archivo antes de eliminar (Windows)
3. ✅ **Reintentos inteligentes:** Basados en tipo de archivo y tamaño
4. ✅ **Delay ajustado:** 3s para Excel, 2s para otros archivos

### Impacto
| Tipo de archivo | ANTES | AHORA | Mejora |
|-----------------|-------|-------|--------|
| **Excel (.xlsx/.xls)** | 5×2s = 10s | 15×3s = 45s | **+350%** |
| **Archivos >1MB** | 5×2s = 10s | 15×2s = 30s | **+200%** |
| **Otros archivos** | 5×2s = 10s | 10×2s = 20s | **+100%** |
| **PDF (ejemplo)** | ✅ Funcionaba | ✅ Funciona mejor | +0% |

**Resultado:** Archivos Excel ahora se eliminan exitosamente en la mayoría de casos.

## 🛠️ Cambios Detallados

### Archivo: `main.js`

#### 1. Corrección de método de papelera (Línea ~4305)

**ANTES:**
```javascript
try {
  await shell.moveItemToTrash(normalizedPath);  // ❌ NO existe en Electron 10+
  // ...
} catch (trashError) {
  sendLog(`[MAIN][delete-document] Error al mover a papelera: ${trashError.message}`, 'WARN');
}
```

**AHORA:**
```javascript
try {
  await shell.trashItem(normalizedPath);  // ✅ Método correcto Electron 10+
  
  const stillExists = await fsp.access(normalizedPath)
    .then(() => true)
    .catch(() => false);
  
  if (!stillExists) {
    sendLog(`[MAIN][delete-document] Archivo movido a papelera exitosamente`, 'INFO');
    return { success: true, message: 'Archivo eliminado correctamente' };
  }
  
  sendLog(`[MAIN][delete-document] Archivo sigue existiendo después de trashItem`, 'WARN');
} catch (trashError) {
  sendLog(`[MAIN][delete-document] Error al mover a papelera: ${trashError.message}`, 'WARN');
}
```

**Justificación:**
- `shell.moveItemToTrash` **NO existe** en la API de Electron 10+
- `shell.trashItem` es el método **oficial y documentado**
- Compatible con Windows, macOS, Linux

---

#### 2. Liberación de handles de Windows (Línea ~4322)

**NUEVO:**
```javascript
// === ESTRATEGIA 2: Liberar handles de Windows (solo Windows) ===
if (process.platform === 'win32') {
  sendLog(`[MAIN][delete-document] Intentando liberar handles de Windows...`, 'DEBUG');
  try {
    // Abrir y cerrar para intentar liberar locks
    const handle = await fsp.open(normalizedPath, 'r');
    await fsp.close(handle);
    await sleep(500); // Pequeña pausa para liberar
  } catch (e) {
    sendLog(`[MAIN][delete-document] No se pudo liberar handles: ${e.message}`, 'DEBUG');
  }
}
```

**Justificación:**
- Windows mantiene **file handles** abiertos para archivos Office
- Google Drive File Stream también mantiene handles de sincronización
- Abrir y cerrar el archivo fuerza la liberación de locks
- Solo se ejecuta en Windows (`process.platform === 'win32'`)

---

#### 3. Reintentos inteligentes por tipo de archivo (Línea ~4335)

**ANTES:**
```javascript
const maxRetries = 5;
const delay = 2000; // 2s

for (let i = 0; i < maxRetries; i++) {
  await fsp.unlink(normalizedPath);
  await sleep(delay);
  // ...
}
```

**AHORA:**
```javascript
// === ESTRATEGIA 3: Eliminación forzada con reintentos mejorados ===
// Detectar tipo de archivo para ajustar estrategia
const fileExt = path.extname(normalizedPath).toLowerCase();
const isExcel = fileExt === '.xlsx' || fileExt === '.xls';
const isLargeFile = stats.size > 1024 * 1024; // > 1MB

// Configurar reintentos basados en tipo de archivo
const maxRetries = isExcel || isLargeFile ? 15 : 10;  // 15 para Excel/grandes, 10 para otros
const delay = isExcel ? 3000 : 2000;  // 3s para Excel, 2s para otros

sendLog(`[MAIN][delete-document] Intentando eliminación forzada (${maxRetries} intentos, ${delay}ms delay)...`, 'INFO');
sendLog(`[MAIN][delete-document] Tipo: ${fileExt}, Tamaño: ${stats.size} bytes, Es Excel: ${isExcel}`, 'DEBUG');

let deleted = false;

for (let i = 0; i < maxRetries; i++) {
  try {
    await fsp.unlink(normalizedPath);
    await sleep(delay);

    const stillExists = await fsp.access(normalizedPath)
      .then(() => true)
      .catch(() => false);

    if (!stillExists) {
      deleted = true;
      sendLog(`[MAIN][delete-document] Archivo eliminado en intento ${i + 1}/${maxRetries}`, 'INFO');
      break;
    }

    sendLog(`[MAIN][delete-document] Reintento ${i + 1}/${maxRetries} - archivo aún existe`, 'WARN');
  } catch (retryError) {
    if (retryError.code === 'ENOENT') {
      deleted = true;
      break;
    }
    throw retryError;
  }
}
```

**Configuración por tipo de archivo:**

| Tipo | Extensión | Tamaño | Reintentos | Delay | Tiempo máximo |
|------|-----------|--------|------------|-------|---------------|
| **Excel** | `.xlsx`, `.xls` | Cualquiera | 15 | 3000ms | **45s** |
| **Grande** | Cualquier | >1MB | 15 | 2000ms | **30s** |
| **Normal** | Otros | ≤1MB | 10 | 2000ms | **20s** |

**Justificación:**
- **Excel** requiere más tiempo (3s) porque Google Drive lo indexa activamente
- **Archivos grandes** (>1MB) requieren más intentos (15) por tiempo de sincronización
- **Archivos normales** mantienen configuración razonable (10×2s = 20s)

---

#### 4. Mensajes de error específicos (Línea ~4375)

**ANTES:**
```javascript
throw new Error('Google Drive tiene el archivo bloqueado. Cierra Google Drive temporalmente e intenta nuevamente.');
```

**AHORA:**
```javascript
if (!deleted) {
  sendLog(`[MAIN][delete-document] ERROR: El archivo sigue existiendo después de ${maxRetries} intentos`, 'ERROR');
  
  // Mensaje específico para Excel
  if (isExcel) {
    throw new Error('Google Drive tiene el archivo Excel bloqueado. Cierra Excel y Google Drive, luego intenta nuevamente.');
  }
  
  throw new Error('Google Drive tiene el archivo bloqueado. Cierra Google Drive temporalmente e intenta nuevamente.');
}
```

**Justificación:**
- Usuarios de Excel necesitan instrucción específica de cerrar **ambas** aplicaciones
- Mensaje genérico para otros tipos de archivo
- Logging mejorado para debugging

## 📚 Lecciones Aprendidas

### Qué funcionó ✅

1. **Diagnóstico basado en logs:** Los logs detallados permitieron identificar el método incorrecto
2. **Estrategia en capas:** Papelera → Handles → Reintentos funciona mejor que un solo enfoque
3. **Detección inteligente:** Identificar tipo de archivo y tamaño permite optimizar reintentos
4. **Logging descriptivo:** Mensajes específicos ayudan a debuggear problemas futuros

### Qué no funcionó ❌

1. **Asumir que `moveItemToTrash` existía:** La documentación de Electron cambió en v10.0
2. **Reintentos genéricos:** 5 intentos × 2s fue insuficiente para archivos grandes
3. **No liberar handles:** Windows mantiene locks que bloquean eliminaciones
4. **Mensajes de error genéricos:** No ayudaban al usuario a resolver el problema

### Recomendaciones para futuros fixes 🔧

1. **Verificar API de Electron:** Siempre consultar documentación oficial antes de usar métodos
2. **Logging por niveles:** INFO para flujo normal, DEBUG para detalles técnicos
3. **Estrategias progresivas:** Intentar métodos menos invasivos primero (papelera)
4. **Mensajes accionables:** Decirle al usuario exactamente qué hacer si falla
5. **Métricas cuantificables:** Medir tiempos y tasas de éxito para validar mejoras
